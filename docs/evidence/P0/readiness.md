# P0 전제·이월 기준

P0 종료 기준의 정본이다. 기능 완료와 해당 단계의 사전 조건을 구분한다.

| 항목 | 결정 또는 처리 | 완료해야 하는 단계 |
| --- | --- | --- |
| 실행 승인 | execution-v1 B 승인, 총괄 이슈 #4의 원문·범위 연결 | P0 |
| 시장·보유 | 국내·미국 현물/일반 ETF, 최대 2 거래일, 정규장, 실적 발표 통과 보유 제외 | P0 |
| 손실 규칙 | 위험 관리일 KST 07:00, 잔여 예산 검사, DB 장애 시 자동 전송 중단 | P0 |
| 리뷰 모델·경로 | 사용자 지시: 로컬 Claude CLI, claude-fable-5-2, high. 실제 modelUsage 확인 | P0 |
| 개발 호출 위치 | 현재 로컬 개발 호스트. 원격 운영 서버의 IP를 개발 API 인증 IP로 가정하지 않음 | P0 |
| CI·재개 지침 | 최종 SHA 문서 CI, 승인·이슈·STATE·PR 읽기 순서 확인 | P0 |
| 키움 자격 증명·허용 IP | 안전한 입력으로 OS 인증 저장소에 저장. API 호출 전 실제 출구 IP와 등록 여부 확인 | P1 실조회 전 |
| 최초 조회 종목 | 국내·미국 각각 조회용 예시 종목으로 연결 시험. 실제 매매 관심 목록과 별개 | P1 |
| 투자 관심 목록 | 사용자 입력 화면에서 등록. 등록되지 않은 종목은 매매 후보 제외 | P4, P5 진입 전 |
| 모의 API의 미국 지원 | 공식 명세·실호출로 확인. 미지원이면 자체 shadow이며 브로커 모의 체결로 표시하지 않음 | P1 조사, P5 검증 |
| UI 기술 | Python API와 React/TypeScript UI. 기존 데이터·위험 계약을 공유하고 최소 화면부터 구현 | P0 결정, P4 검증 |
| Buzz relay·agent identity | 실제 활성 relay를 확인하고 기존 에이전트와 분리 생성 | P4 |
| 리서치 모델·프록시 | Astra·Argon 후보의 실제 가용성과 반환 모델 검증. 로컬 리뷰 성공을 프록시 성공으로 간주하지 않음 | P1 연결, P3 선정 |
| 운영 서버·배포 IP | 모의 운영 대상과 출구 IP·비밀값 전달·시간 동기화를 확인한 뒤 배포 | P5 배포 전 |
| 실전 운용 | 대상 버전·계좌·한도·기간 별도 결정 | P6 결과 후 P7 |

P0 행의 미충족을 이월하려면 사유와 영향받는 승격 조건을 명시해야 한다.
P1 이후 항목의 미완료는 해당 단계에서 해결하며 P0의 실제 제품 기능 성공으로 표시하지 않는다.
