# P1 KIS 읽기 전용 연결 검증

2026-11-11. 사용자 요청으로 키움에서 한국투자증권으로 변경하고 모의투자 API를 선택했다.
P1은 진행 중이며 이 기록은 단계 완료 판정이 아니다.

- 구현: 국내·미국 현재가, 호가, 잔고 조회 6종. 인증 POST 외 업무 요청은 고정 조회 경로의 GET만 허용한다.
- 인증: 터미널 숨김 입력 → OS Secret Service 저장 → 재조회 비교. 비밀값·잔고 원문을 파일이나 공개 결과에 저장하지 않는다.
- 검사: 39개 테스트 통과. Ruff 검사·포맷 검사 및 패키지 빌드 확인.
- RED 근거: 주문 차단·잘못된 환경 테스트의 예외 미발생을 확인한 뒤 구현. KIS 오류 분류 회귀 테스트도 수정 전 실패를 확인했다.
- 실제 요청: 모의 서버에서 국내·미국 현재가와 호가 4종의 성공 응답을 확인했다. 주문 호출은 0이다.
- 실제 실패: 국내·미국 잔고는 HTTP 500, `EGW02007`과 “해당 앱키는 모의투자용 앱키가 아닙니다”를 반환했다. 모의 계좌 연결 성공으로 계산하지 않는다.
- 조치: `environment_mismatch`로 분류하고 후속 probe 호출을 중단한다. 사용자에게 모의 전용 키 재등록 창을 열었다.
- 한계: 실제 잔고·연속 페이지, 거래소 이벤트 시각과 신선도, 시세 이용 권한, 프록시 요청/반환 모델은 미검증이다. 테스트의 연속조회 통과는 실제 계좌 검증을 대신하지 않는다.

## 리뷰

로컬 Claude CLI에 `claude-fable-5-2`, effort `high`를 요청했다.
반환 `canonicalModel=claude-fable-5-2`, `provider=firstParty`, `subtype=success`를 확인했다.
최초 판정은 CHANGES_REQUESTED다. KIS가 본문 코드로 전달하는 호출 제한·인증 오류를 구분하라는 지적을 수용했다.
[공식 오류표](https://apiportal.koreainvestment.com/faq-error-code)와 실제 EGW02007 응답을 근거로 수정했다.
예외의 요청 객체 연결을 제거하고 HTTPX INFO 로그의 계좌 노출 주의사항을 추가했다. 미사용 Pydantic 의존성을 제거했다.
수정분 후속 리뷰는 PASS이며 같은 반환 모델을 확인했다. 입력 SHA-256은 `784c8c46ef70ce84263e642878991fabf70c6505193ef3164bad4aaaa4e307a3`이다.
후속 리뷰의 비차단 지적 2건도 재현 테스트로 확인 후 수정했다: probe는 첫 실패에 중단하며 저장값 JSON 예외 연결을 제거한다. 이 마지막 소규모 수정은 로컬 테스트로 검증했고 외부 리뷰를 반복하지 않았다.
GitHub CI 결과는 PR에서 연결한다. 최초 리뷰를 PASS로 바꾸지 않는다.

## 재개

[운영 명령](../../operations/kis-readonly.md)의 `probe`는 토큰을 한 프로세스에서 재사용한다.
모의 전용 키 재등록 후 probe를 실행한다. 어떤 조회든 첫 실패 시 재시도하지 않고 종료한다.
시세 성공만으로 계좌 환경을 판정하지 않는다. 실전으로 자동 전환하지 않는다.
