# 개발·검증·재개

기준 기록은 [총괄 이슈 #4](https://github.com/krdn/gon-stock/issues/4)와 단계별 이슈다.
최신 main과 현재 작업 PR을 구분한다. 실행 제안은 승인 범위에 맞춰 통합한 버전을 읽는다.

## 환경

Python 3.13을 사용한다. 현재 문서 검사는 표준 라이브러리만 필요하다.

```sh
python --version
python scripts/check_docs.py
git diff --check 4b825dc642cb6eb9a060e54bf8d69288fbee4904 HEAD
```

Python 3.13이 설치된 uv 환경에서는 `uv run --python 3.13 --no-project python scripts/check_docs.py`로 실행한다.
검사는 Git에 등록한 Markdown의 로컬 파일 링크와 코드블록을 확인한다. 외부 URL과 제목 앵커는 검사하지 않는다.

## 실행 순서

1. 작업 트리와 원격 상태, 현재 단계·승인을 읽는다.
2. 작업 이슈를 연결한 branch에서 구현하고 관련 검사를 수행한다.
3. 기능·설계·위험 규칙 변경은 로컬 Fable 5.2 리뷰를 수행한다. 요청·반환 모델과 검토 대상을 남긴다. 사소한 문서·설정은 예외다.
4. PR의 마지막 SHA, 리뷰 지적 처리와 검사 결과를 확인한다. 리뷰 실패나 미해결 핵심 지적이 있으면 merge하지 않는다.
5. 통합 후 main 검사와 수용 기준을 확인하고 다음 작업을 기록한다.

CI의 `docs` 검사는 문서 검사일 뿐 금융 기능 검증이 아니다.
금융·LLM 통합 검사는 승인된 환경에서 실행하고 정제된 결과만 GitHub에 저장한다.

## 중단·재개

STATE와 단계 이슈에 현재 SHA, 완료 검사, 실패·미검증, 다음 행동을 남긴다.
새 세션은 AGENTS → STATE → 단계 이슈와 승인 → PR·검사 → 필요한 설계 순서로 읽는다.
실행 중인 작업이나 미커밋 변경을 확인하지 않고 같은 작업을 새로 시작하지 않는다.

개발 실행 중단은 거래 서비스 중단이나 포지션 청산을 뜻하지 않는다.
