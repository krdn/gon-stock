# P4 결정 카드와 연결 검증

P3 미래 자료가 쌓이는 동안 개발 전체를 멈추지 않도록 사용자가
[P4 병행 개발](https://github.com/krdn/gon-stock/issues/4#issuecomment-6812438087)을 승인했다.
실제 성과 수용과 P5 진입은 계속 보류한다.

## 이번 동작

사용자가 사전 시각·유효기한·종목·출처 묶음을 입력하면 Astra가 제안하고 Fable 5.2가 반론한다.
필요하면 최대 두 번 보완한다. 요청/반환 모델이 다르거나 응답 형식·출처가 잘못되면 실패로 기록한다.
프록시는 기존 사용자 설정을 사용하고 도구·주문 기능은 전달하지 않는다.
Argon의 ID 불일치는 그대로 남기며 다른 모델을 Argon으로 표시하지 않는다.

결과 카드는 언제나 연구 모드·관망·성과 검증 대기다. 확률·기대손익·진입가·손절·목표는
미검증 값으로 채우지 않는다. LLM 찬성은 거래 허용이 아니다. 만료 후에는 만료 상태를 표시한다.
같은 요청 ID는 중복 실행하지 않고 실패·부분 전송도 기록한다. 뉴스 본문의 명령은 자료로만 취급한다.

로컬 화면은 관심 목록 등록·삭제, 결정 카드, 자료 기준시각·만료, 연구 모드와 중단 상태를 보여준다.
보유 상태는 미연결로 표시한다. 기존 수집 DB와 분리해 쓰기 잠금이나 수집 중단을 만들지 않는다.
루프백에서만 서비스하고 외부 Origin의 변경 요청을 거부한다. 외부 스크립트나 분석 추적기를 넣지 않는다.

## Buzz 경계

세 private 채널은 research/signals/ops 용도로 분리한다. 기존 에이전트·권한은 변경하지 않는다.
전용 에이전트 생성은 공식 Desktop 경로로 하고 identity·실제 모델 매핑을 비공개로 기록한다.
인증된 Buzz CLI에서 채널 가시성·구성원·전송 응답과 원격 재조회 내용을 검증한다.
CLI 인증이나 Desktop 제어가 없으면 연동 코드는 검사하되 실제 연결은 NOT_RUN으로 남긴다.
로컬 프록시 역할 응답과 Buzz 전용 에이전트의 응답은 서로 다른 검증 항목이다.

전용 웹 프레임워크 대신 기존 Python과 정적 HTML/JS를 사용한다. 이번 화면의 작은 기능 범위에
맞고 의존성이 늘지 않는다. 다중 사용자나 외부 공개 요구가 생기면 인증·배포 구조를 다시 설계한다.

## 수용 증거

- 잘못된 출처·미래 시각·만료·모델 불일치·형식 오류·중복 요청·보완 상한 검사.
- 관심 목록 저장/재시작과 화면 조작, 연구/미연결/만료 표시 확인.
- 같은 Buzz 스레드의 요청→반론→최종 카드 및 signals/ops 알림 원격 재조회.
- 로컬 Claude Fable 5.2 high 리뷰, 최종 SHA 검사·CI·병합 결과 확인.

소스 검증 없이 URL이 있다는 이유만으로 사실 확인 완료라고 표시하지 않는다. P4의 모델 일치는
프록시 자기 보고 범위이며 백엔드 신원의 독립 증명이 아니다.
